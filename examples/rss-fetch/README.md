## Capabilities

### `rss.fetch`

Fetch an RSS or Atom feed by URL and return its entries as ready-to-use structured fields (title, link, summary, published, id).

**When to use:**
Use rss.fetch when the agent needs structured data from a feed URL.
Typical missions: "summarise the last 5 entries from <feed>",
"poll <feed> for items published since <timestamp>".

The output is already parsed — entries[].title / .link / .summary are
plain strings, so the agent never writes XML-parsing code.

Do NOT use rss.fetch for arbitrary HTML scraping — use http.fetch for
raw HTML and parse downstream.
Do NOT use rss.fetch on auth-required feeds — use http.fetch with the
appropriate headers instead.

**Permission tier:** `notify`

#### Inputs

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `url` | String | Yes | Public HTTP or HTTPS feed URL. file:// and other schemes are rejected at the input boundary (InvalidURL, raised synchronously). |
| `limit` | Integer | No | Maximum entries to return. Default 20, max 100. Out-of-range values are clamped silently. |
| `timeout` | Integer | No | Request timeout in seconds. Default 15, max 60. Lower for monitoring loops, higher for slow feeds. |

#### Outputs

| Name | Type | Description |
|------|------|-------------|
| `entries` | Array | Newest-first feed entries (capped at `limit`). Each is an object with ready-to-use string fields: title, link, summary, published, id. Missing fields are empty strings, never null. |
| `entry_count` | Integer | Number of entries returned — the agent need not call len(). |
| `truncated` | Boolean | True if the feed held more entries than `limit` — the agent need not compare counts. |
| `cache_hint_minutes` | Integer | Suggested minutes to wait before re-polling, parsed from the feed's RSS 2.0 <ttl> or its sy:updatePeriod + sy:updateFrequency. 0 when the feed gives no hint. |
| `feed_url` | String | The final feed URL after following redirects (may differ from the input url). |
| `feed_title` | String | The feed's channel/feed title — the agent need not re-parse it from entries. |

#### Usage Examples

**Summarise the latest N entries:**
```
rss.fetch(url='https://example.com/feed.xml', limit=5)
Summarise the returned `entries` (already newest-first)
```

**Poll a feed for items newer than a cutoff:**
```
rss.fetch(url=feed_url)
Keep entries whose `published` is later than your last-seen timestamp
Record the newest `published` as the next cutoff
```

**Cache-aware polling loop:**
```
rss.fetch(url=feed_url)
Process new `entries`
Sleep `cache_hint_minutes` (fall back to your own interval when it is 0) before the next fetch
```

**Detect truncation and widen the window:**
```
rss.fetch(url=feed_url, limit=20)
If `truncated` is true, refetch with a higher `limit` (up to 100) to see older entries
```

#### Errors

| Type | Description | Recovery |
|------|-------------|----------|
| `InvalidURL` | The url is empty, malformed, or uses a non-http(s) scheme (e.g. file://). Raised synchronously, before any network work. | URL is structurally wrong. Do not retry. Treat the source as suspect. |
| `FetchFailed` | The feed could not be retrieved — DNS, TLS, connection failure, timeout, or an HTTP error status. | Single retry after 5-30s. If second attempt also fails, treat as permanent. |
| `ParseFailed` | The response was retrieved but is not a parseable RSS or Atom feed. | URL does not serve a feed. Try http.fetch instead to get raw bytes. |

#### Side Effects

- Issues one HTTP/HTTPS GET to the feed URL (with redirect follow). (reversible)
